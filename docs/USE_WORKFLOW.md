# USE_WORKFLOW — เอา prompt ไปวางใน workflow แล้วรันเอง

รีโปนี้ช่วย **สร้าง prompt** เท่านั้น ส่วนการเรนเดอร์คุณรันเองด้วย workflow สอนของคอร์ส **"Minimax H3 EZ Workflow"** (ผู้สอนแจกเป็นไฟล์ `.json` และ/หรือเปิดบนเว็บ RunningHub):
**https://www.runninghub.ai/workflow/2111495230942896130**

> ผู้สอนเขียนคู่มือนี้จากไฟล์ workflow ที่แจก ยังไม่ได้ยืนยันว่าหน้าเว็บ RunningHub ตรงกับไฟล์ทุกอย่าง (ชื่อปุ่ม/ตำแหน่ง node อาจต่าง) ถ้าหาอะไรไม่เจอ ให้ถามผู้สอน อย่าเดา

## เตรียมก่อน
- บัญชี RunningHub (https://www.runninghub.ai) และ coins/เครดิตสำหรับรัน (ตรวจราคาและเงื่อนไขในเว็บเอง — คิดเงินตามเวลารัน ไม่รวมเวลารอคิว)
- prompt จาก agent (เป็นไฟล์ `.txt` — เปิดไฟล์แล้วก๊อปจากไฟล์ ไม่ใช่ลากคลุมจากหน้าแชท เพราะแท็กอย่าง `<Picture 1>` อาจหาย)
- รูปตัวละคร (ครอปให้หน้าชัด ตัวเดียว ไม่มีมือ/ลายน้ำ/ตัวหนังสือ), ถ้าเป็นคลิปเต้น: วิดีโออ้างอิงท่า

## หน้าตา workflow (จากไฟล์ EZ Workflow)
- **กล่อง (node) สีแดง = MultiTrack Editor** คือที่เดียวที่คุณต้องแตะเป็นหลัก มี 4 จุด: **1) ความยาวคลิป 2) อัพโหลดรูป 3) ปรับ Resolution 4) ใส่ Prompt**
- ในไฟล์มี Note (กล่องข้อความ) สอนมือใหม่ติดไว้แล้ว รวมถึง Note ที่มี "AI prompt" ให้ก๊อปไปให้ AI ช่วยเขียน prompt (ในรีโปนี้ agent ทำหน้าที่นี้แทน)
- **TOTAL STEPS = 8** (ตัวเลขคงที่ใน workflow) — ค่าเริ่มต้นที่ผู้สอนใช้แล้วภาพดี
- Resolution ในกล่องแดงตั้งไว้ `720 x 1280 (9:16)` (แนวตั้ง) โหมด `stretch` — เปลี่ยนได้ตามแพลตฟอร์ม
- มีกลุ่ม LoRA ที่ **ปิดอยู่เป็นค่าเริ่มต้น** (กลุ่ม "Realism LoRA" เช่น NSGirl, Cinematic, DaSiWa, relim) และกลุ่ม "Turbo LoRA" ที่เปิดอยู่ — ตัวสลับเปิด/ปิดอยู่ใน node ที่ชื่อ Fast Groups Bypasser ตอนเริ่มอย่าเพิ่งแตะ ลองผลปกติก่อน แล้วค่อยลองเปิดทีละตัวเพื่อเทียบ

## ขั้นตอน
1. เปิดหน้า workflow ข้างบนและ **ลองรันตัวอย่างที่มีมาให้หนึ่งครั้งก่อน** เพื่อดูว่าบัญชีคุณรันได้
2. ที่กล่องสีแดง ใส่ **รูปตัวละคร**
   - ถ้าลากรูปมาวางแล้วขึ้นว่า "หาไฟล์ไม่เจอ / not found" ให้กดปุ่ม **+** แล้วเลือก **upload** แล้วเลือกรูปจากเครื่อง (วิธีนี้ชัวร์สุด ตาม Note ใน workflow)
   - ถ้าเป็นคลิปเต้น วางวิดีโออ้างอิงท่าที่ video track
3. วาง prompt ในช่อง prompt ของ segment — ถ้ามีหลาย segment วางทีละ segment ตามลำดับไฟล์ (`..._segment1`, `..._segment2` หรือ `H3_SEG1`, `H3_SEG2`)
4. ตั้ง **ความยาว segment**: เฟรม = วินาที × 24 (เช่น 12 วินาที = 288 เฟรม) **ไม่ควรเกิน 15 วินาทีต่อ segment** (ยิ่งยาวยิ่งเจนนาน) segment แรกเป็นแบบ "shot" ที่เหลือเป็น "context" (ต่อเนื่อง)
5. ตรวจค่าที่ใช้แล้วภาพดี (ผู้สอนทดสอบกับเวอร์ชันของตัวเอง): **steps 8**, **megapixels ประมาณ 1.0**, 24 fps; กฎโดยประมาณ: เฟรม × megapixels ไม่เกิน ~540 ต่อ segment
   - ปุ่ม megapixels/sampling mode ในไฟล์ EZ อาจถูกซ่อนไว้ ถ้าไม่เห็น ไม่ต้องหา ใช้ค่าเริ่มต้นของ workflow
6. **ทดลองสั้นๆ ก่อน (3–5 วินาที)** เพื่อประหยัดเครดิต แล้วค่อยรันยาว
7. กดรัน รอผล ดาวน์โหลดคลิปเก็บทันที (RunningHub เก็บผลลัพธ์ได้ไม่นาน ผู้สอนเคยสังเกตราว ~14 วัน ตรวจเงื่อนไขล่าสุดเอง)
8. จดผลที่ได้ (ดีตรงไหน เพี้ยนตรงไหน) ให้ agent ช่วยปรับ prompt รอบถัดไป

## ปัญหาที่เจอบ่อย
- ลากรูปแล้วขึ้น "หาไฟล์ไม่เจอ": ใช้ปุ่ม **+ → upload** แทนการลากวาง
- ท่าเต้นไม่ตามวิดีโอ: ตรวจว่าไม่มี timestamp ในส่วนสีหน้า และไม่ได้เขียนท่าทางเอง (ดู `docs/RULES.md`)
- ตัวละครร้องเพลง/พูดเอง: ระบุปากให้ชัด (silent dancer) และเขียนเสียงบรรยากาศใน `overall_soundscape`
- ชุดไม่ตรงรูป: ตรวจว่าข้อความไม่ได้บรรยายชุดขัดกับรูป (ข้อความชนะรูป)
- มือ/นิ้วเพี้ยน: ลดจำนวนท่าต่อ shot ให้เหลือท่าเดียว
- ภาพกว้างกว่าที่เขียน: ใช้รูปตัวละครที่หน้า–อกเต็มเฟรม และเขียนขนาดภาพให้ชัด
- ตัวหนังสือในภาพเพี้ยน: อย่าให้ภาพมีตัวหนังสือ ใส่ตอนตัดต่อแทน
- ไม่แน่ใจว่าผลเสียเงินเท่าไร: ดูหน้าราคา/ประวัติการใช้ในบัญชี RunningHub ของคุณเอง
